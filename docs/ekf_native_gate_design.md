# EKF 原生门控设计（替代 s_tilt_bad_s / gate_ekf_tilt / mag_rs 一堆启发式）

> 目标：把"质量门 + 抬 R + 失效计时器"全部删掉，改成**只调 Q 与 R 的诚实卡尔曼**：
> 地磁 R 用真实常数；陀螺侧的"不确定度"按**总旋转量**与**时间**生长；重力牵引发生时按比例**减小而非重置**。
> 本文只做数学可实现性验证与设计，不动代码。

## 1. 误差模型（单轴，小角）

```
δθ̇ = b + w          w: ARW 白噪, PSD q_arw        （姿态误差）
ḃ  = w_b            w_b: 零偏随机游走, PSD q_b     （陀螺零偏）
```

每步（dt）过程噪声：

```
Q_θθ = q_arw·dt + (k_s·|ω|·dt)²      ← 第二项 = 标度误差 k_s(实测 0.0015~0.002) 乘【本步旋转量】
Q_bb  = q_b·dt
Q_θb  = 0
```

观测：地磁 `z = ψ_meas`，`R_mag = σ_m²`（**常数**，σ_m = 标定+站位的绝对误差 ≈ 2°，实测 1.5~2.5°）；
重力（加速度）`R_grav = σ_a²`，仅在"加速度确实在测重力"时给（质量门 = `|a_lin|`/NIS，与姿态几何无关）。

## 2. 三个性质的数学验证

### 2.1 绝对不确定度按"总旋转量"和"时间"单调生长 ✓

- 姿态（倾斜）项：`P_θθ(t) ≈ q_arw·t + (k_s·θ_rot(t))²` ⇒ 由**累计转角**主导；
- 偏航项：零偏不可观时 `P_bb(t) ≈ P_bb(0) + q_b·t`，投影到偏航 ⇒ `P_ψψ(t) ≈ P_ψψ(0) + P_bb(0)·t² + q_b·t³/3`
  ⇒ **从启动起单调增长**，正是"偏航 R 单调增加"想要的形态。

### 2.2 相对运动精度不被破坏 ✓（这是关键，也是"偏航 R 单调增长"单独做不到的）

设 `u(t)=δψ(t)`。相对量 `Δu = u(t2) − u(t1)`（t1,t2 邻近）：

```
Var(Δu) ≈ q_arw·|t2−t1| + P_bb(t1)·(t2−t1)² + (k_s·Δθ_rot)²
```

- 第一项 = ARW（与开机多久无关）；
- 第二项里的 `P_bb(t1)` 是**零偏的后验方差**（被地磁更新过，是小的、有界的），不是 `P_bb(0)+q_b·t1`；
- ⇒ **`Var(Δu)` 与 t1（已运行时长）无关**，只与 Δt 和 Δθ_rot 有关 ⇒ "开机一小时后的相对精度 = 开机时" ✓✓

**所以数学上的正确表述是**：把误差看成"白噪部分 + 零偏积分部分"，**零偏必须是一个状态**（本工程已有 `IX_BG`）。
`Δu` 里零偏项以 `(t2−t1)²` 进入、系数是零偏的**后验**方差；而 `u(t)` 的绝对项以 `t²` 进入、系数是零偏的**先验+后验**方差。
**代价**：若只有姿态状态、靠"抬高偏航过程噪声 R/Q"来模拟"绝对不确定度增长"，那么 `q·dt` 会同时进入 `Var(Δu)` 的第一项 ⇒ 相对精度被一起毁掉（开机越久、相对越差），这是错的建模。

### 2.3 "减小而非重置" ✓ 就是卡尔曼增益本身

地磁/重力一次更新：`P ← (I−KH)P`，`K = P/(P+R)` ⇒
- 单次观测**永远只按比例**减小 P（不会归零）✓
- 牵引时长短（只来一两帧）⇒ P 只减一点点 ⇒ **不会因"过短牵引"把模型重置成"我已很准"** ✓✓
⇒ 现在代码里的 `s_tilt_bad_s = 0`（硬重置计时器）正是要删掉的那个"错误重置"。

### 2.4 交叉点自动涌现（无需任何 gate）✓

`K = P/(P+R)` ⇒ `P ≪ R` 时滤波几乎不信观测（陀螺驰豫：相对精度保住），`P ≫ R` 时才重信观测。
- **倾斜**：`P_θ = (k_s·θ_rot)²` 与 `R_mag = σ_m²` 相等时 `k_s·θ_rot = σ_m`
  ⇒ `θ_rot* = 2°/0.002 = 1000°` ⇒ **810 dps 时 1.23 s**（实测交叉点 1.25 s ✓）、300 dps 时 3.3 s、100 dps 时 10 s。
- **偏航**：`P_ψ = (σ_b0·t)²` 与 `R_mag` 相等时 `t* = σ_m/σ_b0 = 2°/0.02~0.05dps = 40~100 s`
  ⇒ 启动后 40~100 s 内偏航基本纯陀螺（相对精度满血），之后绝对航向才逐渐被地磁对齐。

**结论**：τ 与门限都不用写死；`k_s`、`σ_m`、`σ_b0` 三个**物理可测**的量就能生成全部行为。

## 4. 可实现性核查

1. **状态齐备**：`IX_Q`(姿态)、`IX_BG`(零偏) 已有 ⇒ 无需加状态，只改 `Q` 的构造（每步用 `|ω|`、`dt`）与 `R` 取值 ✓
2. **量纲/自洽**：`(k_s·|ω|·dt)²` 与 `q_arw·dt` 同量纲（rad²）✓；`k_s` 无量纲 ✓
3. **数值稳定性**：绕 b̂ 方向的方差会持续增长，必须靠重力观测（`b̂ ∦ ĝ` 恒成立，夹角=90°+dip=144.3°，sin=0.583 ⇒ 条件数仅 1.72×）按比例回落；需保持 Joseph 形式与 P 对称化 ✓
4. **不会出现的奇异**：`b̂ ∥ ĝ` 只在 dip=±90°（磁极）成立 ⇒ 本站及全部飞行包线内死点不可达 ✓
5. **风险点**：`k_s` 低估 ⇒ 大旋转后 P 偏小 ⇒ 地磁被过度信任（把 2° 绝对误差灌进刚转完的姿态）；`k_s` 高估 ⇒ 地磁过早介入，破坏相对精度。所以 `k_s` 必须取**实测值**（0.002），这就是"平衡点"本身。

## 5. 验收设计（烧录后）

1. **5 min 静置**（测 2.2）：绝对航向应呈现先慢后快的对齐；任意 10 s 窗口的**相对**航向变化误差应停在 ARW 量级（与开机时刻无关）——若随运行时长变差，说明"时间项放错了状态"。
2. **060459 同动作 A/B**：过渡窗修正的绕 ĝ 分量（现 −32.5°）、幕数（现 17）、累计（现 691°）、真静止静差（现 1.81°）四项齐降。
3. **交叉点实测**：从数据反推 `K` 随 `θ_rot` 的变化，应过 `θ_rot ≈ 1000°`（810 dps 段 ≈1.2 s）。
4. **长静置绕 b̂ 检查**：静差 ≤0.5°（重力满权重钉住，条件数 1.72×）。

| 阶段 | 内容 | 说明 |
|---|---|---|
| **S3（当前）** | **高精度标定**：三轴陀螺标定（识别 3 轴标度 + 对称交叉轴 K）→ 交叉轴补偿做在 EKF 之前；零偏由追踪器零速直接测量预校正并按"单向播种 + P0_bias 取追踪器证据"接入 EKF | 目标：`k_s` 从"含交叉轴的 0.002"降到干净值（预期 0.0005~0.001），`σ_b0` 从 0.05 降到 0.005 dps ⇒ 陀螺独占期 ×2~4（机动）/×10（静置） |
| **S4（顺延）** | GPS 融合 | 从原计划顺延到 S3 之后 |

误差预算（降权后，历时 T）：`e = ε_m + b_err·T + k_s·θ_rot + ARW·√T`
- `k_s·θ_rot`：交叉轴预校正 ×2~4（**任意机动保持均成立，与地磁历史无关**）
- `b_err·T`：零偏预校正 ×10
- `ε_m ≈ 2°`：地磁绝对误差地板，陀螺侧无法消除

**保持期零偏的兜底必须来自传感器层（追踪器，零速直接测量、与地磁无关）**；EKF 的 `IX_BG` 只作"地磁可用期的便利态"（它会把 σ_m 吸进去，实测站位残差在两次录像间差 8°、dip 差 1.5° ⇒ 不稳定，不可作为降权后的基准）。

## 8. 与 8 kHz 对接的现实情况（据代码，非猜测）

- 帧注释：**固件积分用 dt ≈ 124.66 us ⇒ 8.02 kHz**；而记录的 `dt_us` 实测 **2989 us = 24 × 124.66**，正好等于调试分频（`V5F_CDC_DEBUG_DIV = 24`）⇒ **记录是 24× 抽取，不是 8 kHz 全量**（日志帧率 334.5 Hz 与此吻合）。
- 因此"M7/M8 EKF 自身被调用的频率"与"ISR 频率"**是两个数**，需要单独确认；代码里存在 `s_w_int[3]`（永不归零的陀螺角增量积分）+ `s_w_snap` 快照机制 ⇒ 说明 EKF 是**多速率**消费累积增量的结构。
- 传感器上限：ICM-42605 的 ODR 上限就是 8 kHz ⇒ 再往上没有源数据；能提升的只是"EKF 每帧都跑（8 kHz）"而非 334 Hz 消费一次。
- **目前没有周期/执行时间计数器**（全程 grep：无 cycle counter、无 max_us、无超期检测；唯一计时原语是 `GetTime64_Us()`，只用于 i2c 软超时与 OLED 空窗）。⇒ "EKF 能不能跑到 8 kHz"**只能靠加一条计时探针实测**，不能推算：建议在 `proc_ekf` 各阶段首尾取 `GetTime64_Us()` 求差、在帧里追加"本帧处理耗时 / 历史最大耗时"两列，即可直接读出裕量（同时得到"最小 dt 能压到多少"）。
## 9. VER=117：算力探针（本轮唯一改动，独立于 S3 标定，便于单独 A/B）

- `SPI_rx.c`：`s_pr_n/sum/max/ovr` 累加器（19 行）+ 每帧累加（898-899 行，紧跟原有 `s_dma1_irq_us = d;`）+ 访问器 `v5f_isr_probe_1s()`（926 行，1 s 窗口，读时若被中断打断只影响一帧计数，无害）。
- `SPI_rx.h`：追加原型。
- `main.c`：主循环首部 1 Hz 打印（**绝不在 ISR 里 printf**）：`[V5F] isr <n> Hz avg <a> us max <m> us load <p.pp>% ovr125 <k>`。
  - `n` = 每秒实际帧数 ⇒ **直接读出处理链（含 M7/M8 EKF）的真实频率**，一下解决"8 kHz 还是被 24× 抽取"这个悬案；
  - `avg/max` = 每帧 ISR 用时（含全链 + 组帧）；`load` = `avg*n/1e4` %；
  - `ovr125` = ISR 用时 > 125 µs（超过 124.66 µs 标称周期）的帧数 ⇒ 时间裕量告警。
- 备份：`bak_src\V5F\User\{src\SPI_rx.c,inc\SPI_rx.h,main.c,inc\v5f_tune.h}.bak_v117`
- 回退：`Copy-Item bak_src\V5F\User\src\SPI_rx.c.bak_v117 V5F\User\src\SPI_rx.c -Force`（其余三个同理）。
- 判读：若 `n ≈ 8000` ⇒ 全链已在 8 kHz，问题只剩裕量；若 `n ≈ 334` ⇒ 链被抽取（`s_w_int`/`s_w_snap` 累积结构），提高 EKF 频率就是把它改成每帧调用。`load` 直接给出算力余量，`ovr125` 给出能否再提频。
### 9.1 实测结果（VER=117 首次运行，2026-09-21）

```
[V5F] isr 8029 Hz  avg 21 us  max 58 us  load 16.86%  ovr125 0
```

- **全链（8 个处理函数含 M7/M8 EKF）已在 8029 Hz 跑** ⇒ 之前"EKF 可能只有 334 Hz、靠 s_w_int 累积"的猜测**被否证**；日志里的 334.5 Hz 纯粹是调试抽取 24×（8029/24 = 334.5 ✓ 与实测 dt_us 2989 us 完全吻合）。
- 算力：周期 124.66 us，均值 21 us（16.86%）、最劣帧 58 us（2.1× 余量）、`ovr125 = 0` ⇒ **平均余量 ~5.9×**。
- 结论：8 kHz 已达（ICM-42605 ODR 上限就是 8 kHz），提频无意义；S3/S4 的所有新增（三轴标定、EKF 原生 Q/R、交叉轴前置补偿、GPS 融合）在算力上**都不构成约束**（即便 EKF 成本翻 4 倍，负载仍 ~67%）。
- 真正约束在别处：**记录带宽与 24× 抽取**（代码自带预算：41 路 196 B = 1.57 MB/s）。若要高码率分析数据，动的是抽取倍数/USB 带宽，不是 EKF 频率。
- 口径提醒：日志是 24× 抽取的，凡我按"每日志帧"换算的速率（如磁注入 dqx/dqy ≈ 12 deg/s）需按该列是"每 EKF 步"还是"抽取区间累计"复核，比值结论不受影响；高码率窗口的陀螺扣减用的是 334 Hz 快照，属采样误差，姿态净变化量（取自 q）仍精确。
