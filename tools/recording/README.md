# 录制工具（tools/recording/）

> **定位**：把板子的 CDC 二进制流无损落盘。本目录只放**采集工具与协议**，
> 不含任何分析脚本（分析脚本不进仓库，见 §4 纪律）。
>
> 建立日期：2026-10-15

---

## 1. 文件

| 文件 | 作用 |
|---|---|
| `record.ps1` | ★ 主采集脚本：串口 → 文件，抗 USB 瞬断、自动重连、写事件日志 |
| `record.cmd` | Windows 批处理包装（免记参数） |
| `mag360_recording_protocol.md` | 整圈录制协议（姿态覆盖要求、判据、自检） |
| `录制工具用法.txt` | 原始用法便签（内容为空，正式说明见本文件与 `record.ps1` 头部注释） |

**`record.ps1` 顶部注释已包含完整用法**，摘要如下（细节以脚本内注释为准）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File record.ps1 -Secs 60
powershell -NoProfile -ExecutionPolicy Bypass -File record.ps1 -Secs 300 -Port COM5
powershell -NoProfile -ExecutionPolicy Bypass -File record.ps1 -Secs 60 -Port auto -Baud 115200
```

| 参数 | 说明 |
|---|---|
| `-Secs` | 采集时长（秒，墙钟），**必填** |
| `-Port` | `COM3` = WCH-Link 调试串口（USART1，文本日志）；`COM4` = 板载 USB CDC（二进制流）；`auto`（默认）= 取**最大** COM 号，优先 CDC |
| `-Baud` | 默认 921600（CDC 忽略波特率，但值需合法） |
| `-Out` | 输出文件，默认 `R:\rec_<stamp>.bin` |
| `-IdleMs` | 空闲看门狗：多久没有新字节就判掉线并重连（默认 500 ms） |
| `-RetryMs` | 重连轮询间隔（默认 25 ms） |
| `-NoReconnect` | 关闭自动重连（旧行为，仅作对照） |

## 2. 两个必须知道的设计点（脚本头部原话）

```
① 为什么需要"空闲看门狗"：
   USB 信号线瞬断时，Windows 的 SerialPort 常常【不抛异常】，
   BytesToRead 一直返回 0。纯 try/catch 重连永远不会触发，
   症状是"脚本还活着但文件不再增长"。所以必须同时用"多久没有新字节"来判掉线。

② 断开时【不关闭】输出文件：
   文件流只打开一次（Create truncate），重连只重开端口。
   重连前后的字节落在同一个文件里，不会截断。

③ 事件日志写到 <Out>.events.log：每次掉线与恢复的时刻、停机毫秒数，
   事后可与帧数缺口（magmap gap_report）交叉核对。
```

## 3. 录制侧纪律（来自各文档，汇总在此）

```
1. 输出目录：R:\（RAM 盘）与 _recordings/（持久盘）应各留一份。
   ★ 注意：R:\ 是 RAM 盘，重启即失；只留 R:\ 等于没留。
2. .bin 按仓库 .gitignore 约定【不入库】（*.bin 被忽略）。
   ⟹ 录制必须由本地备份承担，且必须落在【持久】位置。
3. 每份录制必须记录：日期时间、器件配置（SET/RST 周期、档位）、
   动作类型、以及参考判据（见 docs/接力_*.md §4.3 的表格格式）。
4. 姿态覆盖要求见 mag360_recording_protocol.md：
   零点标定类录制必须遍历三维球面；覆盖不足的录制不能用于标定。
```

## 4. 本目录的边界（★ 重要）

```
✗ 不放分析脚本       —— 防止把过程性尝试固化成"事实"，见下
✗ 不放录制 .bin      —— 体积 + .gitignore 约定
✗ 不放构建/烧录产物  —— 由使用者自行完成；本仓库不提供构建烧录流程
✓ 放采集工具与协议
✓ 放官方手册与厂商资料（docs/datasheets/）

★ 知识污染防护：
  本项目明确【不得参考分析源脚本的实现】。工作区里曾存在大量一次性分析脚本
  （v3 根目录 2084 个 .py），它们承载的是【当时的过程性尝试】，其中
  相当一部分后来被证否（例如以模长为判据、以自制阈值切静置平台、
  在近共面点集上做球拟合等）。
  把这些脚本放进仓库，会让后来者把它们当成"已验证的方法"照搬，
  从而把已被否证的思路复活。
  ⟹ 判据、事实与常数溯源一律以【文档】为准，不以脚本实现为准。
```
